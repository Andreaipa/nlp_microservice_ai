Todas las cifras provienen del conjunto de **test**: 15 cilindros y 90
fotografías que no intervinieron en el entrenamiento. La separación se hace
por identidad de cilindro, nunca por imagen, para que la evaluación mida
generalización y no memorización.

## Sistema completo

```
identificación correcta ........ 31.1%   (60% en tomas cercanas)
correcto o entre las 4 opciones  40.0%
errores silenciosos ............  0.0%
requiere confirmación manual ... 100.0%
CER medio del serial ...........  0.254
latencia mediana / p95 ......... 857 ms / 1682 ms
```

</Aside>

## Detector

Sobre cilindros no vistos en entrenamiento:

| Clase          | mAP50 |
| -------------- | ----- |
| Global         | 0.301 |
| `marking_area` | 0.447 |
| `serial_text`  | 0.155 |

El detector **no es el cuello de botella**: localiza la zona troquelada con
confianza en torno a 0.83. La clase `serial_text`, que acota la línea concreta
del número, sí está floja, y eso tiene consecuencias (ver más abajo).

## Qué movió cada cambio

Historial de lo que se probó y lo que consiguió:

| Cambio                                   | Efecto                          |
| ---------------------------------------- | ------------------------------- |
| RapidOCR en lugar de PaddleOCR           | latencia 8,8 s → **0,67 s**     |
| Corregir el filtro de posición vertical  | anotaciones 92 → **326**        |
| Entrenar el detector (72 → 247 imágenes) | mAP50 0.147 → **0.301**         |
| Emparejamiento por fragmento             | acierto 18,9% → **22,2%**       |
| Buscar el serial dentro de lo leído      | acierto 22,2% → **31,1%**       |
| Reconocedor propio desde cero            | **empeoró**: CER 0.597 vs 0.537 |

Entrenar el detector mejoró la latencia y la calidad de los recortes, pero no
la precisión de identificación. Lo que sí la movió fue aprovechar mejor lo que
el OCR ya leía, contrastándolo con el inventario cerrado (ver abajo).

## Lo que enseñaron las pruebas con teléfono

Las primeras pruebas con la app sobre cilindros reales (serie `K57…`, el 31%
del inventario) mostraron que buena parte del fallo no era del OCR sino de
cómo se interpretaba lo leído:

- El troquelado lleva un espacio en medio ("K5738 060") y el OCR lo devolvía
  en dos trozos que nadie volvía a unir.
- Se proponía el fragmento leído con más confianza, que solía ser otra marca
  ("PW200", la presión de trabajo), en lugar del que existía en el inventario.
- Con un umbral de error fijo, "300" se daba por el cilindro "804".
- De las tres variantes de realce, sólo contaba de verdad la "mejor": las
  lecturas de las otras se descartaban.

La corrección busca cada serial del inventario **dentro** de todo lo leído,
une los trozos de una misma línea, tolera errores en proporción a la longitud
del serial y descarta las marcas que no son seriales (presiones, fechas,
número ONU). Con ella, ofrecer alternativas sí sirve:

|                                       | Antes | Ahora   |
| ------------------------------------- | ----- | ------- |
| El correcto es el propuesto           | 22%   | **31%** |
| El correcto está entre las 4 opciones | 24%   | **40%** |
| Propone un número equivocado          | 53%   | **27%** |

Con menos propuestas equivocadas, cuando el sistema no está seguro deja el
campo vacío y pide otra foto en lugar de sugerir un número que confunde.

## Limitaciones conocidas

<Tabs>
  <TabItem label="Etiquetas adhesivas">
En el Cilindro_034 el serial `171392042` está visible en la fotografía y el
sistema leyó `201707`, que es la fecha estampada debajo. El OCR había
reconocido además `TRUJILLO`, `Argonindustal` y `161048355`: todo texto
**impreso** de las pegatinas del collarín.

Es comprensible, porque el texto impreso tiene mucho más contraste que el
troquelado. El remedio es mejorar la clase `serial_text` (mAP 0.155), para que
el recorte que llega al OCR no contenga etiquetas.

  </TabItem>
  <TabItem label="Encuadre ambiguo">
Dos de cada seis tomas marcadas como `3.Cerca` no muestran el collarín: una
encuadra el cilindro entero y otra se acerca a la válvula, por encima de la
zona estampada.

"Cerca" debe significar **cerca del troquelado**, no cerca del cilindro. El
[protocolo de captura](/datos/protocolo-captura/) lo precisa.

  </TabItem>
  <TabItem label="Seriales cortos">
Doce cilindros del inventario tienen seriales de seis caracteres o menos. En
una fotografía del cilindro `21S062189` el OCR leyó el fragmento `20640`, que
es el serial **completo** del Cilindro_015.

Todos esos seriales quedan marcados para confirmación obligatoria. Remarcar
esos doce cilindros con un código más largo eliminaría el problema.

  </TabItem>
</Tabs>

## Reproducir estas cifras

```bash
make evaluate    # sistema completo sobre el test
make calibrate   # curva de umbrales
```

Los informes quedan en `models/pipeline_metrics.json` y
`models/threshold_calibration.json`.
